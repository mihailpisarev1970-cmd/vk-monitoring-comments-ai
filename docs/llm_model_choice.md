**Статус:** выполнено 2026-11-17 (ТЗ п.12.1); модель сменена на `claude-haiku-4-5` 2026-11-18
**Base URL:** `https://aidostup.site/v1` · **Авторизация:** `Authorization: Bearer sk-…`
**Модель в эксплуатации:** `claude-haiku-4-5` (`AIDOSTUP_MODEL`)

> Изначально использовалась `claude-opus-5-5`. По решению заказчика модель
> заменена на `claude-haiku-4-5`. При смене проверено: классификация 4/4
> верных решения, генерация комментария валидна. Для компенсации более
> слабого контроля длины у быстрой модели валидатор теперь сравнивает слова
> по основе (падежные формы), а генератор подрезает затянутый комментарий
> по границе предложения вместо полной регенерации.

## 4. Генерация комментариев

Требования ТЗ п.13.1: 200–300 символов, русский язык, живой стиль, реакция на
конкретное содержание, без шаблонов, без рекламы, без выдуманных фактов.
`temperature=0.7`.

| Публикация | Длина | В диапазоне | Оценка |
|---|---|---|---|
| Вопрос про aiogram vs pyTelegramBotAPI | 329 | ❌ (+29) | содержательный ответ, но длинновато |
| Техническое решение (идемпотентность callback) | 246 | ✅ | уместный уточняющий вопрос |
| Мнение о регламентах перед автоматизацией | 282 | ✅ | развёрнутая мысль, без шаблонов |

**Наблюдение:** без явных указаний по длине модель систематически
перебирает (302–368 символов). После добавления в промпт требования
«целевой ориентир 240–270 символов, если больше 290 — сократить»
попадание в диапазон выросло до 2 из 3. Финальная версия промпта на
этапе 5 будет использовать:
1. явный диапазон + самопроверку длины в промпте;
2. валидацию в коде (`200 <= len <= 300`) и повторную генерацию
   с дополнительной инструкцией (ТЗ п.13.2);
3. отсечение служебных строк вида «Подсчёт символов: …».

## 5. Оценка стоимости

По документации AiDostup: `(input + output токены) × multiplier`.
Один цикл мониторинга ≈ 10 запросов × ~200 постов = до 2 000 публикаций,
**но** после технических фильтров в LLM уходят единицы.

При 20 публикациях в сутки после префильтров:

| Модель | ×mult | Токенов/сутки (оценка) | Относительная стоимость |
|---|---|---|---|
| `claude-opus-5-5` | 4 | ~80 000 | 1× (базовая) |
| `deepseek-v4-pro-0813` | 0.7 | ~80 000 | ≈ 0.17× |
| `gpt-6-luna` | 0.3 | ~80 000 | ≈ 0.08× |

Кэширование системного промпта у Anthropic-моделей уже работает
(`cache_creation_input_tokens` / `cached_tokens` в `usage`), что снижает
реальный расход на повторяющийся промпт.

Оба идентификатора задаются только через `.env` (`AIDOSTUP_MODEL`,
`AIDOSTUP_COMMENT_MODEL`), в коде не зашиты (ТЗ п.12.1).

### Замечания по надёжности API

- На часть запросов `claude-opus-5-5` отвечала 17–22 с — клиент **обязан**
  иметь таймаут ≥ 60 с и повтор при таймауте.
- Один запрос завершился `TimeoutError` на уровне TCP-соединения
  (WinError 10060) — нужен retry с backoff.
- Повторять безопасно только `429` и `503` (по документации); при
  `400/401/402/403` повтор бессмыслен.
